# AGENTS.md

## Работа с проектом

- Отвечай на языке пользователя. Сначала читай историю задачи, README.md, CHECKLIST.md и относящийся к задаче журнал docs/LOTOS_PREMIUM_PLAN.md.
- Действуй самостоятельно в согласованных границах. Спрашивай, когда решение о продукте неизвестно или действие выходит за авторизованный объём.
- Проверяй выводы по коду и результатам проверок. Сохраняй существующие пользовательские изменения, не откатывай и не переформатируй посторонний код.
- CHECKLIST.md хранит решения о продукте. Не добавляй отсутствующие или удалённые возможности без запроса пользователя.
- Единственный сайт — website/, Astro SSG, React, TypeScript, Tailwind CSS и GSAP. Backend, БД, отдельное приложение, Storybook и облачная инфраструктура удалены.
- LICENSE и NOTICE сохранять. CLAUDE.md только импортирует этот файл.

## Реализация

- Исправляй причину в модуле, которому принадлежит поведение. Предпочитай небольшое согласованное изменение без новых абстракций.
- Страница и layout собирают разделы; функциональность находится в src/features, общие утилиты — src/lib, используемые UI-примитивы — src/components/ui.
- Сохраняй визуальный язык и границы UI-компонентов. Не меняй дизайн при технической очистке.
- Новые зависимости требуют согласования, если пользователь прямо их не запросил. Для библиотечных API проверяй актуальную документацию и локальные типы; для документации используй Context7, когда он доступен.
- Для изменения поведения начинай с узкой проверки регрессии. Для визуальных и технических правок используй пропорциональную проверку без тестов, повторяющих реализацию.
- Демо-форма не отправляет и не сохраняет данные. Не подключай реальную отправку без запроса.
- Не редактируй сгенерированные tour.json и медиа вручную. Подготовка выполняется внешним скриптом из соседнего lotos/ по README.md; сохраняй текущие пути website/.
- Не выдумывай цены, контакты, комплектацию, отзывы или подтверждение общей площади. Визуализации не являются фотографиями построенного дома.

## Проверки и документация

- Используй Bun и команды package.json. Если инструменты отсутствуют в PATH, используй PATH="/opt/homebrew/bin:$HOME/.bun/bin:$PATH".
- bun run check проверяет типы, тесты экскурсии/навигации, сборку и статические контракты. Все проверки выполняются локально.
- Для интерфейса проверяй затронутые сценарии в браузере на ПК и узком экране; сохраняй fallback без JavaScript, при reduced-motion и ошибке видео.
- Не выдавай исторические проверки за повторно пройденные. Сообщай о сбоях и непроверенных сценариях прямо.
- Обновляй README, CHECKLIST и журнал, когда меняются запуск, границы продукта или важные решения. В итоговом ответе кратко укажи изменения, проверки и ограничения.

## Git и безопасность рабочей папки

- Перед операциями с веткой, коммитом, push или PR проверь git remote -v. Не публикуй в репозиторий исходного шаблона.
- Не создавай и не переключай ветки, не используй worktree, не копируй репозиторий без явного запроса. Никогда не используй git stash.
- Не выполняй stage, commit, reset, rebase или push без явного запроса. Не удаляй файлы вне согласованной задачи.
- Не настраивай публикацию и GitHub Actions без запроса; проверки только локальные.
- Не останавливай процессы для освобождения порта; используй свободный порт.
- Не выводи секреты и содержимое .env. Не ослабляй проверки безопасности.
- Временные артефакты помещай в .scratch/ или временную папку инструмента и удаляй после проверки. Не трогай соседние lotos/ и lotos 2/ при работе над сайтом, если это не запрошено отдельно.
